# Automation Test Engineer

## Purpose

This article describes the Automation Test Engineer working pattern within `ROLE-QA` — candidates who write and maintain code-based scripts and frameworks that test an application without manual execution.

## Scope

This article covers what typically distinguishes an automation-focused candidate from the other three working patterns in this collection, for sales-conversation purposes only.

## Core Content

Candidates in this pattern describe their work through the lens of building repeatable, automated checks — scripts and frameworks that run a test suite without a person stepping through it by hand. Many came into this pattern after starting in manual testing and picking up scripting or programming skills over time, while others entered with a programming background already in place. This mixed entry path is itself a useful discovery signal, since it shapes how a candidate talks about their own trajectory and what they're looking for next.

This pattern sits at a meaningful midpoint in the collection: closer to code than [Manual QA Tester](/docs/candidate-intelligence/qa-testing/manual-qa-tester), but still centered on testing as the primary discipline rather than general application development, which is what distinguishes it from [SDET](/docs/candidate-intelligence/qa-testing/sdet).

## Cross-Module Alignment

This pattern gives specific shape to the automation-focused population the [QA & Testing Playbook](/docs/industry-playbooks/qa-testing-playbook) describes generally, and its code-based framing shares some vocabulary with [Backend Specializations](/docs/candidate-intelligence/software-engineering/backend-specializations) in the Software Engineering collection without being the same working pattern.

## Advisor Guidance

Ask specifically how a candidate's automation skills developed — whether from a manual-testing starting point or a programming background — since that history often shapes what kind of next step they're evaluating. Be precise about the distinction between manual and automation-focused work rather than treating QA as one undifferentiated category.

Automation Test Engineers build and maintain code-based automated checks, often arrive at this pattern from either manual testing or a programming background, and sit at a meaningful midpoint between the collection's least and most code-centric working patterns.

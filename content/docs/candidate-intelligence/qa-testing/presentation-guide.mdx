# Presentation Guide

## Purpose

This guide applies the existing Discussion module to `ROLE-QA`, continuing this collection's four-stage advisor playbook.

## Scope

This guide covers presentation-call approach for QA Testing candidates broadly, building on [Presenting Surely Placed](/docs/discussion/presenting-surely-placed) and [Explaining the Process](/docs/discussion/explaining-the-process).

## Core Content

Consistent with [Presenting Surely Placed](/docs/discussion/presenting-surely-placed), present the recommendation in language that reflects the candidate's specific working pattern rather than a generic "QA" framing — naming manual testing, automation, leadership, or SDET work accurately, per [Candidate Behaviour](/docs/candidate-intelligence/qa-testing/candidate-behaviour), does real work toward building trust with this population.

When explaining the process per [Explaining the Process](/docs/discussion/explaining-the-process), if the candidate raised a skill-direction question during discovery — such as whether to build automation skills — address it directly here rather than leaving it unresolved, since per [Buying Patterns](/docs/candidate-intelligence/qa-testing/buying-patterns) this is often a genuine open question the candidate is actively weighing.

Where the candidate's working pattern is [SDET](/docs/candidate-intelligence/qa-testing/sdet), be prepared to discuss how the recommendation accounts for their dual fit with Software Engineering, rather than presenting only a QA-specific framing.

## Cross-Module Alignment

This guide applies [Presenting Surely Placed](/docs/discussion/presenting-surely-placed) and [Explaining the Process](/docs/discussion/explaining-the-process), shaped by this collection's credibility-sensitivity findings.

## Advisor Guidance

Use precise language for the candidate's specific working pattern, address any skill-direction question raised during discovery directly, and account for dual-field fit when presenting to SDET-pattern candidates.

Presenting to this role family works best when it uses precise language for the candidate's specific working pattern, directly addresses any open skill-direction question, and accounts for dual-field fit where a candidate's background sits near the boundary with Software Engineering.

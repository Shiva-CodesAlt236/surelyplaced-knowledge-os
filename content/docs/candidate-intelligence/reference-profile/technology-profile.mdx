# Reference Profile: Technology Profile

> This article is part of the Gold Standard reference profile — an illustrative archetype, never a real person. No specific programming language proficiency level, tool version, or skill rating is stated as fact about a real individual; this demonstrates the *format* a technology summary should take.

## Purpose

[Technology Mapping](/docs/candidate-intelligence/TECHNOLOGY_MAPPING) defines `technology_summary` as a short, factual, non-evaluative field. This article shows what that field looks like when actually written for the reference candidate, modeling the tone and scope future profiles should use.

## Layer 1 — Candidate Identity

Consistent with `role_category: "ROLE-SWE"`, the reference candidate's technical background is generally described as early-career software engineering: familiarity with at least one general-purpose programming language and some exposure to standard development practices, without a claimed specialization in any narrower area (data, security, cloud infrastructure) that would instead point toward one of the other Industry Playbook categories.

## Layer 2 — Sales Intelligence

An early-career candidate with this general technical background is more likely to be still forming their sense of which specialization to pursue, which can make them receptive to a broader conversation about career direction rather than arriving with a narrowly fixed target — a pattern consistent with the early-career framing in [Software Engineering Playbook](/docs/industry-playbooks/software-engineering-playbook).

## Layer 3 — Advisor Playbook

An advisor preparing for a conversation with a candidate matching this technology profile should review [Software Engineering Playbook](/docs/industry-playbooks/software-engineering-playbook) beforehand, consistent with [Meeting Preparation](/docs/sales-operations/meeting-preparation), and should route any question requiring genuine technical evaluation to internal technical SMEs rather than attempting to assess the candidate's skill level directly, consistent with [Technology Mapping](/docs/candidate-intelligence/TECHNOLOGY_MAPPING).

## Cross-Module Alignment

This article demonstrates `technology_summary` exactly as scoped in [Technology Mapping](/docs/candidate-intelligence/TECHNOLOGY_MAPPING) — factual, short, and free of any competence judgment. It intentionally avoids naming specific languages, frameworks, or tools as fixed facts about this archetype, since a real candidate's specifics should come from the candidate directly, not be assumed from their role category.

## Key Takeaways

The reference candidate's technology profile is deliberately general — early-career software engineering background, without invented specifics about particular languages, tools, or skill ratings. A real profile's `technology_summary` should be this concise and this factual, populated only with what a real candidate has actually stated.

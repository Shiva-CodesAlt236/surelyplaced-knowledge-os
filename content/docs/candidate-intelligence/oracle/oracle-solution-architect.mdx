# Oracle Solution Architect

## Purpose

This article describes the Oracle Solution Architect working pattern — candidates responsible for how database, enterprise applications, and integration technology fit together across an organization's broader technology landscape.

## Scope

This article covers what typically distinguishes a senior, cross-product candidate from the other three working patterns in this collection, for sales-conversation purposes only. It names no specific certification level.

## Core Content

Candidates in this pattern describe designing how multiple parts of this broad ecosystem connect for an organization — how a database layer supports a set of applications, how those applications integrate with outside systems, and how the overall technology landscape should evolve over time. Most carry substantial prior experience in one or more of this collection's other three patterns, and often describe the shift into architecture as one from deep expertise in a single layer to breadth across several.

Because this ecosystem is unusually broad, this population is often the most careful of all four patterns about confirming which specific slice of that breadth a given opportunity actually involves before engaging further — a program described only as "Oracle" without specifying database, applications, integration, or some combination leaves real ambiguity this population wants resolved early.

## Cross-Module Alignment

This pattern sits at the senior end of the spectrum this collection documents, drawing on the database, applications, and technical-build focuses of the other three working patterns without being defined by any single one of them.

## Advisor Guidance

Ask which of the other three patterns the candidate's background grew out of, and specify clearly which slice of this ecosystem's breadth — database, applications, integration, or a combination — a given opportunity actually involves before going further. This population responds well to that precision and is cautious without it.

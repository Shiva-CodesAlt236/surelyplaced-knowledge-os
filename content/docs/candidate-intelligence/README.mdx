# Candidate Intelligence Framework — README

> **This sprint defines structure only.** No actual Candidate Intelligence Profile, real or composite, is created anywhere in this module. Every example in these nine articles is explicitly illustrative, clearly marked, and contains no real or invented candidate data, salary figures, or hiring statistics.

## Purpose

Discovery, Visa Playbooks, Industry Playbooks, Pricing, and Sales Coaching each capture a piece of how an advisor understands a candidate — qualification signals, visa timeline, industry mindset, buying psychology, coaching observations. This framework exists to standardize how that understanding gets recorded once a candidate relationship has enough history to document, so future Candidate Intelligence Profiles are structured consistently rather than each advisor inventing their own format.

## Scope

This module defines the schema, taxonomies, and authoring guidelines a future profile-writer will use. It does not populate a single profile. Any future sprint that creates real or composite Candidate Intelligence Profiles will build on this framework — this sprint is the standard those profiles will be checked against, not an example of one.

## Standard Structure

This README sits at the top of eight structural documents, each covering one piece of the overall framework: [Profile Schema](/docs/candidate-intelligence/PROFILE_SCHEMA) defines the complete field set, [Profile Template](/docs/candidate-intelligence/PROFILE_TEMPLATE) provides the blank, fillable document, and [Role Classification](/docs/candidate-intelligence/ROLE_CLASSIFICATION), [Visa Mapping](/docs/candidate-intelligence/VISA_MAPPING), [Industry Mapping](/docs/candidate-intelligence/INDUSTRY_MAPPING), [Technology Mapping](/docs/candidate-intelligence/TECHNOLOGY_MAPPING), [Buyer Persona Schema](/docs/candidate-intelligence/BUYER_PERSONA_SCHEMA), and [Coaching Signals](/docs/candidate-intelligence/COACHING_SIGNALS) each define one classification system used within that schema. [Profile QA Guidelines](/docs/candidate-intelligence/PROFILE_QA_GUIDELINES) closes the module with how a completed profile should be checked once one is eventually written.

## Required Fields

Not applicable at the README level — required fields are defined article by article in [Profile Schema](/docs/candidate-intelligence/PROFILE_SCHEMA) and the six classification documents it depends on.

## Relationships with Other Modules

This framework is a structural layer over the existing Knowledge OS, not a replacement for it. Role and industry classification draw directly on the nine categories already established in Industry Playbooks; visa classification draws on the seven categories in Visa Playbooks; buyer persona fields draw on the psychology established in Pricing; coaching signal fields draw on the reading framework established in Sales Coaching. A Candidate Intelligence Profile, once written, should read as a structured index into those modules for a specific candidate — not a duplicate of their content.

## Author Guidelines

Read this README and [Profile Schema](/docs/candidate-intelligence/PROFILE_SCHEMA) fully before using [Profile Template](/docs/candidate-intelligence/PROFILE_TEMPLATE) to draft an actual profile in a future sprint. Use the classification documents' defined codes and categories rather than inventing new ones. Where a candidate's actual situation doesn't map cleanly onto an existing category, follow the "Category Pending" pattern established in the mapping documents rather than forcing a fit or inventing a new category unilaterally.
